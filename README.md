# Передержка домашних животных

Приложение для гостиницы передержки домашних животных: веб-интерфейс
на Django и консольная версия, работающие с общими данными.

## Назначение
Приложение передержки домашних животных. Оно помогает
оформлять бронирования, проверять, можно ли принять питомца, подбирать ему
подходящее место и рассчитывать стоимость проживания.

## Технологии
1. Python 3.12;
2. Django 5.2: веб-фреймворк;
3. Django Template Language: шаблоны страниц;
4. HTML: разметка страниц;
5. CSS и Bootstrap 5.3: оформление страниц;
6. JavaScript: небольшое поведение интерфейса;
7. SQLite и SQL: реляционная база данных;
8. JSON: исходные данные и хранилище консольной версии;
9. pytest: автоматизированные тесты;
10. flake8: проверка качества кода

## Целевая аудитория
1. Владельцы кошек и собак, которым нужно оставить питомца на время отъезда
2. Администратор гостиницы, который принимает заявки и управляет бронированиями

## Предметная область
Передержка домашних животных. Владелец временно оставляет питомца в гостинице
на определённые даты. Гостиница принимает животных (учитываются вид,
возраст и наличие прививок), размещает питомца в месте подходящего размера
и берёт плату за каждые сутки проживания

## Основные сущности
1. Пользователь. Участник системы (имя, контакты, роль), от роли зависят права
   1. клиент (владелец питомца) оформляет бронирования для своих питомцев;
   2. администратор (сотрудник гостиницы) управляет местами, видит все заявки,
      подтверждает и отменяет любые бронирования
2. Питомец. Животное клиента (вид, возраст, вес, наличие прививок)
3. Место. Вольер или комната определённого размера (малое, среднее, большое)
4. Бронирование. Заявка на проживание питомца в конкретном месте на даты
   заезда и выезда

## Основные функции
1. Проверка допуска питомца (гостиница принимает кошек и собак
   от 3 месяцев с прививками)
2. Подбор места по весу питомца (малое, среднее или большое)
3. Расчёт стоимости передержки. Тариф за сутки, который зависит от размера
   места, число суток по датам заезда и выезда
4. Просмотр и отмена бронирований. Клиент работает со своими,
   администратор со всеми

## Возможности приложения

В веб-интерфейсе:

1. просмотр мест с фильтром по размеру и занятостью на сегодня;
2. поиск мест, свободных на выбранный период;
3. просмотр питомцев с фильтром «можно принять», проверкой допуска
   и подходящими местами;
4. просмотр бронирований со сроком, стоимостью и статусом, фильтр
   «только активные»;
5. статистика: выручка, загрузка мест, питомцы по видам, популярные места;
6. ближайшие заезды на главной странице;
7. переходы между связанными страницами: от места к бронированию,
   от бронирования к питомцу

В консольной версии:

1. просмотр мест, владельцев и питомцев;
2. добавление владельца и питомца;
3. поиск питомца по кличке или имени владельца;
4. проверка допуска питомца и подбор места по весу;
5. проверка занятости места на выбранные даты;
6. оформление бронирования с расчётом стоимости;
7. отмена бронирования с сохранением его в истории;
8. статистика по бронированиям, питомцам и местам

Добавление, поиск, оформление и отмена пока доступны только в консоли.
В веб-интерфейсе они появятся вместе с формами Django.

## Django-проект и приложения

| Пакет | Назначение |
|---|---|
| `config` | настройки проекта и корневые маршруты |
| `homepage` | главная страница и общий каркас всех страниц |
| `rooms` | страницы мест |
| `pets` | страницы питомцев |
| `bookings` | страницы бронирований |

Для пользователей отдельного приложения нет: в Django есть встроенная
модель пользователя, она понадобится вместе с регистрацией и входом.

View-функции не содержат ни HTML, ни своей логики предметной области.
Они загружают данные через `src/storage.py`, находят объект функциями
`find_*_by_id`, вызывают методы и функции классов ПР3, складывают результат
в контекст и передают его в шаблон через `render()`. Функция `page()`,
которая в ПР5 собирала HTML в Python-строках, удалена.

| Компонент | Ответственность |
|---|---|
| `urls.py` | адрес страницы и имя маршрута |
| `views.py` | получение данных и контекст |
| шаблон | HTML-разметка |
| `style.css` | оформление |
| `main.js` | поведение на стороне браузера |

## Шаблоны

Общий каркас лежит в каталоге шаблонов уровня проекта, он подключён
в `settings.py` через `DIRS`:

1. `templates/base.html`: HTML-документ, Bootstrap, свой CSS, JavaScript,
   подвал и блоки `title` и `content`;
2. `templates/includes/navigation.html`: шапка с логотипом и навигацией

Каждая страница наследует каркас через `{% extends "base.html" %}` и
переопределяет блоки. Повторяющиеся фрагменты вынесены во включаемые
шаблоны и подключаются через `{% include %}`:

| Шаблон | Где используется |
|---|---|
| `rooms/includes/room_card.html` | список мест, подходящие места на странице питомца |
| `bookings/includes/booking_status.html` | список бронирований, страница брони, история питомца |
| `bookings/includes/booking_period.html` | период проживания везде, где выводится бронь |
| `pets/includes/acceptance_badge.html` | допуск питомца |

В шаблонах используются:

1. `{{ ... }}` для вывода атрибутов объектов: `{{ booking.pet.owner.name }}`;
2. `{% for %}` с `{% empty %}` для списков и пустых коллекций;
3. `{% if %}` для статуса брони, занятости места, допуска питомца
   и страниц «не найдено»;
4. `{% url %}` с пространствами имён для всех ссылок;
5. автоматическое экранирование: кличка с HTML-тегами выводится как текст

Маршруты имеют пространства имён `homepage`, `rooms`, `pets`, `bookings`
(`app_name` в `urls.py`) и имена `list` и `detail`, например
`{% url 'rooms:detail' room.id %}`.

### Фильтры

| Фильтр | Пример | Назначение |
|---|---|---|
| `length` | `{{ rooms\|length }}` | количество мест, питомцев, бронирований |
| `default` | `{{ room.name\|default:"Без названия" }}` | значение при пустом поле |
| `date` | `{{ booking.check_in\|date:"d.m.Y" }}` | дата в формате ДД.ММ.ГГГГ |
| `join` | `{{ species\|join:" и " }}` | список видов одной строкой |
| `yesno` | `{{ pet.is_vaccinated\|yesno:"есть,нет" }}` | признак прививок словами |
| `floatformat` | `{{ pet.weight_kg\|floatformat:1 }}` | вес с одним знаком |
| `capfirst` | `{{ pet.species\|capfirst }}` | вид с заглавной буквы |

### Статические файлы

Лежат в `homepage/static/homepage/` и подключаются через `{% load static %}`
и `{% static %}`:

1. `css/style.css`: фон, фирменный цвет, карточки мест, статусы бронирований;
2. `js/main.js`: подставляет текущий год в подвал;
3. `img/logo.svg`: логотип в шапке

## База данных SQLite

Данные перенесены из JSON в базу `data/pet_boarding.sqlite`. С ней работают
списки, поиск, статистика и главная страница. Страницы отдельных объектов
пока строятся по объектам ПР3, потому что используют их методы: допуск
питомца, подбор места, расчёт стоимости. Django ORM на этом этапе не
используется, база подключается стандартным модулем `sqlite3`.

### Таблицы

| Таблица | Поля | Ключи |
|---|---|---|
| `users` | `id` INTEGER, `name` TEXT, `phone` TEXT, `role` TEXT | первичный `id` |
| `rooms` | `id` INTEGER, `name` TEXT, `size` TEXT, `price_per_night` INTEGER | первичный `id` |
| `pets` | `id` INTEGER, `name` TEXT, `species` TEXT, `age_months` INTEGER, `weight_kg` REAL, `is_vaccinated` INTEGER, `owner_id` INTEGER | первичный `id`, внешний `owner_id` на `users.id` |
| `bookings` | `id` INTEGER, `pet_id` INTEGER, `room_id` INTEGER, `check_in` TEXT, `check_out` TEXT, `is_cancelled` INTEGER | первичный `id`, внешние `pet_id` на `pets.id` и `room_id` на `rooms.id` |

```
users 1 ──→ * pets 1 ──→ * bookings * ←── 1 rooms
```

Логические значения хранятся числами 0 и 1, даты строками `ГГГГ-ММ-ДД`.
Схема дополнительно проверяет данные через `NOT NULL` и `CHECK`: размер
места из трёх вариантов, положительный тариф и вес, выезд позже заезда.

### Файлы

1. `sql/schema.sql`: команды `CREATE TABLE IF NOT EXISTS`, повторный запуск
   не ломает базу;
2. `sql/queries.sql`: 15 именованных запросов, каждый с комментарием
   `-- name:` и описанием;
3. `db/database.py`: подключение с `PRAGMA foreign_keys = ON` и
   `row_factory = sqlite3.Row`, чтение запросов из `queries.sql` по имени,
   функции `fetch_all` и `fetch_one`;
4. `db/import_json.py`: перенос данных из JSON методом `executemany` в
   порядке пользователи, места, питомцы, бронирования, с `commit` и
   `rollback` при ошибке

Python-код не содержит текста SQL-запросов: view-функции вызывают запрос
по имени, например `fetch_all("available_rooms", params)`. Значения всегда
передаются параметрами `?`, f-строки для подстановки не используются.

### Запросы

| Запрос | Вид | Где используется |
|---|---|---|
| `room_list` | список | `/rooms/` |
| `pet_list` | список, JOIN | `/pets/` |
| `rooms_by_size` | WHERE с параметром | `/rooms/?size=` |
| `acceptable_pets` | WHERE, IN, JOIN | `/pets/?accepted=1` |
| `booking_list` | JOIN четырёх таблиц | `/bookings/` |
| `active_booking_list` | JOIN, WHERE | `/bookings/?active=1` |
| `available_rooms` | подзапрос NOT IN, параметры | `/rooms/available/` |
| `active_bookings_count` | COUNT | главная |
| `income_summary` | COUNT, SUM, AVG, MIN, MAX | статистика |
| `bookings_per_room` | LEFT JOIN, GROUP BY | статистика |
| `pets_by_species` | GROUP BY, AVG | статистика |
| `income_by_size` | LEFT JOIN, GROUP BY, SUM | статистика |
| `popular_rooms` | GROUP BY, HAVING с параметром | статистика |
| `owners_with_several_pets` | GROUP BY, HAVING | статистика |
| `upcoming_check_ins` | ORDER BY, LIMIT | главная |

### Создание базы

```bash
python -m db.import_json
```

Команда создаёт таблицы, если их нет, очищает их и заново переносит данные
из JSON. Консольная версия по-прежнему пишет в JSON, поэтому после её
изменений базу нужно обновить этой же командой.

## Как запрос становится страницей
```
Браузер: GET /rooms/1/
   ↓
config/urls.py: path("rooms/", include("rooms.urls"))
   ↓
rooms/urls.py: path("<int:room_id>/", views.room_detail)
   ↓
rooms/views.py: room_detail(request, room_id=1)
   ↓   load_all(), find_room_by_id(), is_room_available()
context: room, is_free, bookings
   ↓
render(): rooms/room_detail.html, наследует base.html
   ↓
HTTP-ответ: HTML-страница с кодом 200 или 404
```

| Атрибут | Описание |

### Исключения
Ошибки оформления бронирования образуют иерархию. Любую из них можно
перехватить через общий класс `BookingError`.

```
BookingError
├── InvalidPeriodError      дата выезда не позже даты заезда
├── PetNotAcceptedError     питомец не проходит условия приёма
├── RoomNotSuitableError    место не подходит питомцу по размеру
└── RoomNotAvailableError   место занято на эти даты
```

## Взаимодействие объектов
```
Booking
├── pet  ──→ Pet
│            └── owner ──→ User
└── room ──→ Room
```

1. Питомец хранит объект своего владельца, а не его имя
2. Бронирование хранит объекты питомца и места, поэтому через него доступны
   их данные: `booking.room.name`, `booking.pet.owner.phone`
3. Место проверяет, подходит ли ему питомец: `room.is_suitable_for(pet)`
   обращается к методу питомца `required_room_size()`
4. Бронирование не считает стоимость само, а спрашивает её у своего места
   через `room.cost_for()`
5. Отменённое бронирование остаётся в списке и не блокирует место

## Функции над коллекциями
Операции, которые относятся к одному объекту, реализованы методами классов.
Операции над списками объектов остались функциями модулей:

1. поиск по идентификатору и по части имени;
2. сортировка и подсчёт по видам и размерам;
3. проверка доступности места среди всех бронирований;
4. создание и отмена бронирований;
5. отбор бронирований места и питомца;
6. статистика;
7. загрузка и сохранение данных;
8. ввод данных с проверкой

## Хранение данных
Данные хранятся в каталоге `data` в файлах JSON. В файлах записаны только
данные и идентификаторы связанных объектов, а приложение работает
с объектами.

При запуске `storage.py` создаёт объекты в таком порядке: пользователи,
места, питомцы со ссылкой на владельца, бронирования со ссылками на питомца
и место. Если связанный объект не найден, запись пропускается с сообщением.
При сохранении ссылки на объекты превращаются обратно в идентификаторы.
Если файл отсутствует или повреждён, программа стартует с пустыми данными.

Пользователь:

```json
{
    "id": 1,
    "name": "Иванова Анна",
    "phone": "+7 900 111 22 33",
    "role": "клиент"
}
```

Место:

## Требования
1. Python 3.10 или новее;
2. Django 5.2;
3. pytest;
4. flake8

## Установка
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python -m db.import_json
```

## Запуск программы

Веб-версия, после запуска открыть http://127.0.0.1:8000/

```bash
python manage.py runserver
```

Консольная версия:

```bash
python main.py
```

## Запуск тестов
```bash
pytest -v
```

Тесты проверяют:

1. создание объектов и их атрибуты;
2. строковое представление и преобразование в JSON и обратно;
3. связи между объектами;
4. правила приёма питомцев и подбора мест;
5. правило доступности: второе активное бронирование места на те же даты
   запрещено, отменённое бронирование место не блокирует;
6. исключения при оформлении бронирования;
7. отбор бронирований места и питомца;
8. статистику;
9. базу данных: таблицы и внешние ключи, импорт из JSON, выполнение всех
   запросов из `queries.sql`, поиск свободных мест, HAVING и то, что
   значение параметра не выполняется как SQL
